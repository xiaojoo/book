# 长文阅读

千万字级 TXT 的阅读引擎 + Android 原生壳。按 `Chunk → Layout → Page` 分页，正文永远只按逻辑块随机读，
内存里只留当前阅读窗口附近的几块；阅读位置存字符偏移，不存页码。

## 怎么用

```bash
./gradlew-local.sh :core:test          # 引擎的 28 条判据（含千万字验收）
./gradlew-local.sh :app:assembleDebug  # APK → app/build/outputs/apk/debug/app-debug.apk
```

本机没有 `gradle` 命令，`gradlew-local.sh` 直接用 Gradle 缓存里已解压的 9.7.1（JDK 21）。
装到手机：

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
# MIUI 挡 adb install 时改走：adb push ... /data/local/tmp/x.apk && adb shell pm install -r /data/local/tmp/x.apk
```

   滚动相位不同顶端墨迹会在 112~168 之间走，那是连续滚动在带子边缘把行裁断的固有现象。

   缝进了 `style.id`，所以改它会连着重排（把它从 id 里摘掉，`topInsetComesOutOfTheLayoutNotTheDrawing` 就红）。
   **滚动那一档的缝是给"文字带"的，不是给文档首末行的**：整条带子往里挪、上下两条边缘都裁掉。只垫首行的话

   那份居中零头在滚动这一档**必须按"装满一页"算**（`contentHeight ÷ 行高`），不能去问引擎某一页有几行：

## 设计要点

- **位置**：`BookPosition.absoluteOffset` 是唯一权威。换字号、转屏、改边距后重新分页，再按偏移找回，
  屏幕第一行还是刚才那一行（`ReaderEngine.applyStyle` 会把当前页裁成以该行为首）。页码只在这一版式下有效，所以不落库。
- **块与页分离**：块是稳定数据（默认 16384 字/块），页是当前样式下的派生缓存。
- **缓存**：文本层 LRU 默认 6 块；页缓存默认 24 页；章节分页对象只保留最近 3 章。
- **跳章**：章节索引二分 + 文件 seek，不从头扫。
- **预取**：翻页后在后台把后面 6 页排出来（`PrefetchManager`，单并行度，和主线程靠引擎的锁互斥）。
- **线程**：IO/排版/预取都不在 UI 线程；Compose 只拿"当前一页"，每行一次 `drawText`，一行都不是一个 Compose 节点。
- **测量边界**：`LineBreaker` 是接口——Android 用 `Paint.breakText` 真量（走 minikin 的 Unicode 断行表），
  JVM 测试用近似字宽模型，所以分页算法在没有设备时也能被数字否证。

## 缺点 / 没做


- **只能开 TXT**：EPUB / MOBI / AZW3 / PDF / DOCX 都还没接，选文件时非 txt 的会被拒。
  前四种是同一类活（抽出正文喂给现有排版器：EPUB/DOCX 是 zip + XML，MOBI/AZW3 还要解 PalmDOC/HUFF 记录）；
  PDF 是另一类（系统 `PdfRenderer` 出整页图，保留原版面，不进排版引擎 —— 也就没有字号/行距那套）。
- **夜间模式是真的**：`Chrome` 从一堆常量改成"一颗可观察的 `night` + 白天/夜间两套 `Palette`"，
  外壳四页和状态栏/导航条都读它。真机量过：开一下开关，我的页底色 (246,247,249)→(18,19,22)、卡片 (255,255,255)→(27,28,32)、
  状态栏 (246,247,249)→(18,19,22)，再关回去三处逐位复原，`theme` 读回 0。夜间那套的墨色/强调色取自
  `ReaderTheme.Night` 同一批值，两处不会各说一套。开夜之前的那档纸色记在 `dayBefore` 里，关夜还回原来那档（不是一律拍回纸白）。
- **分界线一律 1 个物理像素**：`1.dp` 在这台机（2.75 倍密度）取整成 3 行。我的页行间的线改成按密度换算的 1px，
  真机沿 x=540 竖向切：只有 y=427 一行是 (227,231,237)，其余全是卡的白；搜索页那条同样改法的线此前量过是
  203:0 / 204:0 / 205:78 / 206:0。书架"添加作品"的虚线框从 `1.dp.toPx()`(=2.75) 改成 `1f`，同一规则，
  这一处还没在屏幕上复量（见下条）。
- **精选是静态壳**：只有版式和"未接入书源"的说明，没有榜单/推荐内容；四张卡片是占位。
- **没有封面图**：书架卡片用书名前两字占位。真封面要接书源或让用户自己带图。
- **搜索的中文输入没法用 adb 直接打**（`input text` 不吃 CJK）：这一轮是把"陈平安/剑来/符纸"先塞进 prefs 的 `recentSearch`，
  再点最近搜索那一行触发真搜索，所以整条路（输入框以外的全部）都验过了；输入框里手打中文那一枪仍要你点一次确认。
- **章末孤行**：`剑来` 每章末尾都有一行 `------------` 分隔线，它会单独占一页。分页没做孤行控制，
  正文也不许动（动了 absoluteOffset 就飘了）。
- **同一份文件在 PC 和手机上入库字数不同**：JVM 与 ART 的 UTF-8 解码器对畸形字节的替换个数不一样
  （`剑来` PC 14,682,212 字 / 手机 14,659,450 字，差 0.16%），所以阅读位置只在"入库的那台设备"上有效。
- 书架"添加作品"那颗虚线框的厚度还没在屏幕上复量：这次要截书架时，前台被他的
  `com.xiaojoo.lightplayer` 占着，探针脚本里的"前台不是本应用就停"挡住了，没有去点他的应用。
- MIUI 自己那根侧边滚动条（x=17..24、#979797 的胶囊）会浮在正文左缘上，不是本应用的控件；
  正文左边距量过是 x=63px，不压字。
- 只吃 TXT。EPUB / CBZ / 在线章节没接，虽然容器结构就是按这个留的。
- 元数据落 `manifest.kv` + 二进制索引，没用 Room。章节数上万后 `chapter.idx` 是一次读满的整表，够用但没做分页。
- 全文搜索是逐块 `indexOf`，没有倒排索引 / FTS5；千万字实测 39ms 所以先不做，但两亿字级别会撑不住。
- `仿真` 是"旧纸绕书脊立起 90°"的近似，不是真书页那种带弧面的翻卷（那要网格变形/着色器）；翻到中途能看到
  纸的侧棱，但不会出现卷起来的圆柱面。
- `上下`（滚动）跨章连续：窗口是"连续若干页段"（一段 ≤6 页，整段不跨章），离上下边缘一个半屏就补一段；
  往下补就把最上面那段剪掉、同时把滚动量同帧减去它的高度，往上补则剪掉最下面那段（那段在视野外，不用校正）。
  只剪"整段都在视野外"的，正在看的那段宁可暂时超预算也不剪。滚动位置仍然只存字符偏移，切回按页模式后位置不丢。
- 往回翻遇到只有几行的极短章，可能看到一次跳动（往前补那一刀依赖 `scrollTo` 不被旧 maxValue 夹住）。
- `上下` 那一档改字号后，游标还会退不到一行以内：`13|60914` 连改四次（17→19→17）读回 `13|60894`，退 20 字 = 同一行的行首（重排后这一行本来就从 60894 起）。再往前往后各滚一屏，位置不再动。
- `自动阅读` 做了，速度是三档「行/分钟」（12/24/48），上下和按页两种模式共用这个口径：
  上下那一档实测 63.6px/s，和 48 行/分 ÷ 79.5px 行高算出来的 63.6 完全吻合；按页那一档 39 行 ÷ 48 行/分 = 48.75 秒一页，
  实测约 50 秒一页。缺点：只有三档、不能无级调速；面板开着、弹「该休息」时它照跑不误（只有休息弹框会让一下）。
- 字体表只扫 `/system/fonts`（和 `/system/fonts/GMSFonts`）：用户自己装到 sdcard 的字体、以及需要下载的字体不在里面，
  也没有字体文件的导入入口。判"认不认识中文"用的是字体自己的 cmap，要求 `中/的/门` 三个字都有字形
  ——`MiSansC_3.005.ttf` 只有 35KB（是个子集），就这样被筛掉了。`.ttc` 要读第 0 个 face，
  而 ttcf 里每个 face 的表偏移是**整个文件的绝对偏移**，不是相对 face 头（读错会读到垃圾 format 号，整款字体被误判成"不认中文"）。
- `繁体转简体` 用平台自带的 ICU transliterator（`android.icu.text.Transliterator`，**API 29 起才有**，低版本那颗开关灰着）。
  K40 上量过：`風雲變色，誰知我劍來？` 32 字进 32 字出、15 个字被换掉；对本来就简体的正文是恒等变换（`changed=0`），
  所以简体书开着这颗开关，整页像素逐字节相同（唯一差异是状态栏的钟）。
  转换只在切正文时做，且**长度一变就整段退回原文**（页上的行是按源文偏移切的，见 `safeConvert`）。
  没验到的一步：手上没有能导入的繁体书（`file://` 走 VIEW 意图在这台机上读不到字节），
  所以"繁体书翻开后屏幕上真的变成简体字"这最后一格要人眼过一遍。
- `休息提醒` 只在这一页开着时计时，退到后台不计时。
- 亮度条改的是本窗口的 `screenBrightness`，不动系统亮度设置；`护眼模式` 是叠一层暖色，不是系统级滤光。
- 横屏、副屏、异形屏没量过（K40 竖屏验的）。状态栏/导航栏底色和图标明暗已经跟主题。
- 段落识别只认换行，不做首句加粗、诗词居中这类版式。
- 避头点只按一组常见标点位，没有完整行压缩规则；拉丁长词会硬断。
- 没有进度云同步、没有笔记导出、没有 TTS。
- 章节标题识别是启发式五条规则（第X章/节/回…、Chapter N、"1、…"、"001你到底是谁"这种裸编号、序章/番外等）。
  认错会让一章碎掉，所以配了三道兜底：含句末标点的行不算标题、短于 40 字的"章"吞进后一章、
  超过 20 万字的章在段落边界上切开（排版单元必须有界）。仍可能漏掉写法特殊的标题。
