# 长文阅读

千万字级 TXT 的阅读引擎 + Android 原生壳。按 `Chunk → Layout → Page` 分页，正文永远只按逻辑块随机读，
内存里只留当前阅读窗口附近的几块；阅读位置存字符偏移，不存页码。

## 怎么用

```bash
./gradlew-local.sh :core:test          # 引擎的 60 条判据（含千万字验收、epub/docx/mobi/pptx/md 抽正文）
./gradlew-local.sh :app:assembleDebug  # APK → app/build/outputs/apk/debug/app-debug.apk
```

本机没有 `gradle` 命令，`gradlew-local.sh` 直接用 Gradle 缓存里已解压的 9.7.1（JDK 21）。
装到手机：

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
# MIUI 挡 adb install 时改走：adb push ... /data/local/tmp/x.apk && adb shell pm install -r /data/local/tmp/x.apk
```

界面（底部四个 tab：书架 / 精选 / 书签 / 我的；按 2026-10-08 你给的纵横截图版式改的外壳）：

   **底栏那条的底色 = 界面底色**（`Chrome.page`，日 `#F6F7F9` / 夜 `#121316`），和阅读页两条工具栏同一条规则：
   不单独开一档 bar 色，只靠顶上一条 1 物理像素发丝线分界；系统导航条也改成同一个 token（原先它铺的是卡片白，
   等于同一条栏两个主人）。外壳四页从此共用 `Chrome.page` 一个背景色。

1. **书架**：右上角三颗点 = 一个只有两行的弹框：第一行在**图墙 / 列表**两种排布之间换（文字按当前模式取反，
   图墙下写「切换至列表模式」，列表下写「切换至图墙模式」），第二行「本地导入」= 选本地书入库；
   选中的那种排布会记住（`shelfList`）。图墙 = 3 列卡片（卡片面用书名前两字占位，没有封面图就不放假图），
   末尾多一颗虚线「添加作品」；列表 = 一行一本，左边小封面 + 右边三行（书名 / 作者 · 读到哪 / 章数 · 字数），
   卡片外壳和封面尺寸跟「精选」那一行同一份。能开的格式：**txt**（UTF-8 / GB18030 自动判）、
   **epub**、**docx**、**mobi / azw3**（PalmDOC LZ77）、**markdown** —— 这五种都是抽出正文喂给同一个排版器，字号、行距、
   边距、纸色六档、翻页、书签、搜索全都有（markdown 额外带一层样式，见下面「开 md」那行）；
   **pdf** 和 **pptx** 走另一条路（整页渲染、保留原版面：翻页点屏幕左右 1/3，放大**双指在页面上张合**，
   点屏幕中间放出来的**下面那条栏就是抽屉** —— 跳页输入框 + 「前往」，pptx 还有「播放」和速度，见「缺点」）。
   进度显示在顶上；抽不出正文的（DRM 加密、HUFF/CDIC 压缩）回一句人话说明为什么，不会当成 txt 吞进去。
   长按一张卡片 = 删这本书（二次确认是**从底部推上来的抽屉**，和「偏好设置」那颗同一份 `ModalBottomSheet` 外壳；
   只删入库副本，原文件不动）。

   行距 97dp；实测我们这边封面高 226px/参考 225、行距 264px/参考 266）。这一页原来是整屏纯白（唯一一个不跟
   界面底色的页面），现在跟其余三页同底色，列表**做成卡片** —— 外壳照书签那一档同一份（卡外缩进 12dp、
   圆角 10dp、卡缝 10dp、卡面 `Chrome.card`），封面左缘还是 19dp：拆成"卡外 12 + 卡内 7"，做成卡片不该把内容挪位。
   代价是行距从 97dp 变成 97+10=107dp（多了那道卡缝），这一处**还没在屏幕上复量**。六本书的标题、简介、分类、标签和封面
   **全部是从截图里抄/裁的样例数据**，点一行只会在顶上回一句"书源未接入，加不了书架"。上线前必须整块换掉。
   **长按正文选中整段**（按页和上下两档都行）：选中那一段铺一层墨色 18% 的底，屏幕下面浮出动作栏 ——
   图标在上、文字在下、一行五颗：`评论 听书 词典 纠错 书签`。**动作栏贴在选中段落的上面**，
   只有选的是第一段（上面放不下）才落到下面；**不画边框，靠底色浮起来**（用面板那颗 `bar` 色，六档各有对应色）。
   **选中底色铺到两端对齐后的右边界**：字距拉开后一行实际占宽 = natural + 字数×tracking，
   原来按量出来的 natural 铺，右边就缺一截（他圈出来的那条）。量过：选中行底色右到 **x=997**
   = 版心右边界 1080-82.5（正文墨迹 86..994）。**加过书签的段落下面画红色波浪线**（`drawLines` 里逐行
   画 quad 曲线，整段每一行都标，宽度用同一个 `drawnWidthPx`）：点完书签 `marks` 立刻重算，波浪线当场出现，
   收起选中后还在。当场量过：长按后底栏区变化 14875px、正文区
   （选中底色）52371px；点正文或按返回键收起后再截一张，**与未选中时逐像素相同（0px 差）**。
   五颗里 **书签是真做**（点一下存档从 `marks = 2|5874;13|59237` 变成 `...;13|60780`，记的是这一段开头的偏移）；
   **听书接系统 TTS**，这台 K40 没装中文语音引擎，所以它回一句「这台机没有可用的中文语音引擎」
   （引擎还在启动时会回另一句，不含糊过去）；**词典接的是你自己配的 AI**（见下面「AI 服务」），
   没配的时候点它回一句"还没配 AI 服务：我的 → AI 服务…"，配了就把选中那段的拼音 / 释义 / 译文回在底部面板里；
   **评论 / 纠错没有后端**，点下去只回一句缺什么，不装成能用。
3. **书签**：跨书的标记列表，每条显示书名、章名、第几字和那一行开头的正文；点一条 = 把那本书的位置设成它并直接打开；
   右侧「删」删掉这一条。
4. **我的**：真数（N 本 / 已入库字数 / 已读字数）、导入入口、阅读配色三档、清除全部书籍（红色，二次确认）、关于。
   其中一行是 **AI 服务**（右侧写「未配置 / 已配置」）：点进去是**另开的一整屏**，不是弹窗 ——
   顶栏 `‹ AI 服务 …… 保存`，中间一张卡片三格（API 地址 / 模型名 / 秘钥，秘钥默认打点、旁边一颗「显示 / 隐藏」，
   存过之后那一格留空表示"不改"，屏幕上从不回显已存的秘钥），下面「试一下」发一条最小请求把结果回在旁边，
   再下面是几行规则说明。地址填 `https://x/v1`、`https://x/v1/`、`https://x` 都会被归一成
   `https://x/v1/chat/completions`（已经填到底的不重复拼）；填 `http://` 时地址下面会红字标出"明文走网络"。
   同一屏下面还有一节 **语音（听书）**：先三选一挑服务商（OpenAI 兼容 / MiniMax / 阿里 Qwen-TTS，选完下面三格的示例文字会跟着换），
   再填 语音地址 / 语音模型 / 音色 / 语音秘钥 四格 + 一颗「试听」（合成一句固定的试听词，播着时那颗变「停止」）。
   词典和听书是**两个主人**：对话地址和语音地址可以完全不同，秘钥也各存一份。
5. **书架的网格是量出来的**（参考截图 1080 宽）：左右边距 64px=23dp、封面 232x318=85x116dp、列间距 128px=46dp。
   改完实测我们这边：左边距 63px、封面宽 234px、列间距 126px（差 1~2px 是 dp 取整）。
   封面圆角 4dp，未读点 7dp，品牌红 `#E30000`（截图在变暗遮罩下量到 `#5A0000`，按 0.396 的透光率反算）。
   卡片副标题用参考截图同一口径：**`N章未读`**（章号来自存档位置），不再写"读到 0%"这种看不出东西的百分比。
6. 开书后是阅读页（没有 app 的 tab 栏）。底栏四颗图标+文字：`目录 / 书签 / 夜间(切日间) / 设置`。
   点设置出**快捷面板**（照参考截图）：亮度条 + 跟随系统、`A- 17 A+` + 系统字体、翻页四档
   `平移 仿真 上下 简洁`（选中是红框红字）、5 个纸色色块、底行 `护眼模式 | 搜索 | 更多设置`。
   底行的「关闭」按他要删掉了；收面板剩两条路，都当场量过：点正文（面板底色 y=2200 从 #F2F4F7 回到 #FFFFFF）、
   系统返回键（同样回到 #FFFFFF）。亮度滑轨的高度压到和滑块同直径（都 66px = 24dp；
   原来轨 30dp、滑块 24dp，两头各冒出 3dp，看着就是背景比圆高）。
   **更多设置**（阅读设置页）：行间距 5 档 `松散 较宽 适中 紧凑 密集`、边距 3 档、段首缩进、
   音量键翻页、屏幕常亮、点击两侧均翻到下一页、休息提醒（不提醒/15/30/60 分钟，到点弹一层）、
   **自动阅读**（三档速度，上下模式连续推、按页模式定时翻页）、**繁体转简体**（平台 ICU）。
   **这些档位改完当场生效，不用退回书架重开**：行间距 紧凑→松散 实测行距 55px→80px（=37.9px×1.45/×2.10），
   同一章从 4 页重排成 6 页；边距 较宽→较窄 实测左右墨迹同时从 64/64 移到 41/41；上下滚动那一档也一样活
   （55→80px）。踩过的坑：版心原先在组合作用域里读 `prefs.linePreset`，而 SharedPreferences 不是可观察状态，
   改了档位这个式子根本不会重算，才要重开 —— 现在把三档当**参数**传进 `pageStyle(...)`，Compose 才看得见依赖。
   正文区**分成三屏：左 1/3 上一页、中间 1/3 收起/放出工具栏、右 1/3 下一页**（K40 上分界线在 x=360 / x=720；
   实测点 x=400 只出菜单不翻页、点 x=200 上一页、点 x=900 下一页），也支持左右滑翻页；再点一次屏幕收回工具栏，
   **音量键翻页时菜单/弹层会自动收起**（按完当场量：页码 3/4→4/4，同时屏幕上读不到栏了）。
   弹层开着时先收回弹层。落在面板自身空白处的点击会被面板吃掉（实测：面板开着时点行距，翻页计数 0、面板仍在原位），
   只有点到面板外的正文上才关面板。顶栏常驻"‹ 返回图标 / 章名 / 章内页码 / 全书进度"，系统返回键的次序是
   `选中段 → 字体面板 → 快捷面板 → 收起工具栏 → 回书架`（不会一击退出程序）。
   **上下两条工具栏是纯浮层，不占版心**（顶栏 44dp、底栏 58dp），所以开合菜单不参与排版；
   **版心上下各留一条 5px 的缝**（`EDGE_INSET_PX`，不跟左右「边距」那一档走），两条缝都**从版心高度里扣**，
   不是画的时候往外推：推的话行数不变，最后一行会顶到系统导航键上。
   他那一档（17sp + 紧凑 1.45 + 较宽 30dp）量出来，栏收起时：**按页**整页第一行墨迹 y=113（离状态栏 29px）、
   最后一行墨迹 y=2234（离底 34px）—— 那 29px 里只有 5px 是缝，另外的 17px 是"这一页排不满的零头对半劈开"的
   居中量、8px 是行盒自带的上伸部。**上下（滚动）用同一个矩形**：带子边缘 = 按页那一档行盒的顶边，不再额外加
   行盒上伸部 —— 之前多加的那 8.5px 让滚动整块文字比按页低一截（他两张截图量出来第一行墨迹 121 vs 115），
   切换时看着就是"内容动了一下"。现在同一位置两档并排量：**按页 y=113 / 上下 y=113，逐字相同**；
   另一半"刷一遍"是进滚动那一档时锚位等 effect 去 `scrollTo`，第一帧画的是锚页页头 ——
   现在建 `ScrollState` 那一刻就把滚动量落到锚行上（开书后第 2 秒与第 5 秒内容区逐像素比对 = **0 差异**）；
   滚动相位不同顶端墨迹会在 112~168 之间走，那是连续滚动在带子边缘把行裁断的固有现象。
   缝是从版心高度里扣的，不是画的时候往外推：推的话行数不变，最后一行会顶到系统导航键上。
   缝进了 `style.id`，所以改它会连着重排（把它从 id 里摘掉，`topInsetComesOutOfTheLayoutNotTheDrawing` 就红）。
   **滚动那一档的缝是给"文字带"的，不是给文档首末行的**：整条带子往里挪、上下两条边缘都裁掉。只垫首行的话
   滚动时行照样从状态栏底下穿过去，等于没垫（这就是他报"上下也和原来一样"的那一轮）。
   那份居中零头在滚动这一档**必须按"装满一页"算**（`contentHeight ÷ 行高`），不能去问引擎某一页有几行：
   落在只有一两页的短章上（《新书感言》一章一页）问来的行数偏小，零头顶到行高上限，顶缝当场变成 60px
   —— 就是他圈出来报"这个上下间隙不是 5px"的那个状态。
   工具栏展开时首末行还会被栏压住，收起就完整露出来。

   **原文段与段之间的空行保留**：这批 TXT 每段之间本来就空着一行（`content.txt` 实测每段前一个空行），
   排版器为它排一条零长度的行占住行高（`ParagraphCursor.blankLinesAt` + `PageComposer`），绘制端跳过零长度行，
   所以看上去就是段间那条空隙（17sp 一行 55~56px，实测每页 5~10 处）。绝对偏移仍然逐字连续，书签/续读不受影响。
   **章名那一行顶格、放大 1.25 倍、加粗**（`TextLine.titleScale`，`drawLines` 里换字号 + fakeBold，基线按倍数下压）：
   量过标题行墨迹高 49px / 正文行 40~41px（1.20 倍），左墨迹 x=86 = 正文左缘 86（正文段落首行 x=171 = 缩进 2 字），
   墨迹密度 35.9% / 正文 23.4%。可用宽度先按倍数除掉，标题长也不会顶出右边界。
   **全项目取消点击反馈**：`Modifier.tap` 显式传 `indication = null`，根上再把 `LocalIndication` 换成不画东西的一颗
   （只换根上那处不够 —— 按住 A+ 时芯片中心从 242 掉到 177，还是从触点扩散开的圆）。量法：按住不动截屏，
   与未按时逐像素比，应用区变化 **0 像素**（唯一 1106 个变化像素在状态栏的网速/电量上）。
   `上下`（滚动）和按页两种模式共用同一份左右版心：同一屏左右墨迹都是 **86 / 86**（1080 宽屏）。
   **按页那一档翻页时，两层都裁在同一个内容矩形里**（左右 = 版心边距，他这一档 30dp = 82.5px；上下 = 文字带边缘）：
   平移/仿真是整屏平移和绕书脊转的，不裁的话正文会一路画到屏幕两边 —— 录屏帧量过，翻到中途整屏墨迹横跨
   `x=0..1079`，左右缝里（x 26..58 / 1022..1054）最多一帧有 **18508px** 的字。裁完之后同样的录屏
   （平移 34 帧、仿真 42 帧）缝里墨迹 **0 帧 0px**，而静止那一页逐字没动（第一行 y=115、末行 y=2234；
   正文墨迹左右 85..995，离裁切框还留着 2.5px，不会被啃字）
   `上下` 那一档的首屏：整页原样进文档，把游标之前那几行算进"上面垫了多少"（`anchorPx`），滚动量落到游标那一行。之前是裁一页进文档，前一段到 60079 为止、锚段从 60662 起，**中间 583 字在文档上凭空没有** —— 屏上就是一条比行距大两三倍的空隙（量过 5 处：104/188/133/166/155px，中位行距 55px）。改完连按四次字号：41 / 36 / 41 行，空隙 0 处。
   矩形就是滚动那一档的带子边缘，所以两档之间切换排版不挪。

   **栏的底色和正文同色**（不再单独一档 bar 色），只靠一条 1px 发丝线分界：顶栏画下边、底栏画上边，
   线色 = 墨色按 12% 压进纸色（六档配色共用这一条规则，不各写 hex）。顶栏高 44dp（试过压到 34dp，
   但那道白带其实在正文版心顶上、不在标题栏里，已改回去）。
   顶栏的 ‹ 图标和章名要同一条墨迹中心线：
   `ic_back.xml` 的墨迹原本落在视口 y 3.9..24.1（中心 14，视口中心 12），整体抬高 2 单位后
   图标墨迹中心 145.0 / 标题墨迹中心 144.5（改之前差 5px）。
   **手机状态栏和底部导航条跟着纸色走**：夜间 `#0F0F0F`、宣纸 `#FFFFFF`、豆青 `#CFDBC1`，三处（状态栏/正文/导航条）
   按 token 对齐到 Δ0，并关掉了系统的 contrast enforcement。
   **两端对齐**：段中行的余量摊进字距（上限 0.40 字号），段末行不拉伸；实测整行左墨迹 63~67px、右墨迹 1011~1016px，
   对 1080 宽的屏两侧各留 64~67px。
   **段首缩进 2 个汉字**：网上抓的 TXT 段首常手打 2~4 个空格，排版层把它们当不存在（缩进由版式给，正文和
   `absoluteOffset` 都不动）；实测缩进 120px→**78px**，字号 38px，即 2.06 字（原来是 3.2 字）。
   入库产物落在 `filesDir/books/<id>/`。

## 设计要点

- **位置**：`BookPosition.absoluteOffset` 是唯一权威。换字号、转屏、改边距后重新分页，再按偏移找回，
  屏幕第一行还是刚才那一行（`ReaderEngine.applyStyle` 会把当前页裁成以该行为首）。页码只在这一版式下有效，所以不落库。
- **块与页分离**：块是稳定数据（默认 16384 字/块），页是当前样式下的派生缓存。
- **缓存**：文本层 LRU 默认 6 块；页缓存默认 24 页；章节分页对象只保留最近 3 章。
- **跳章**：章节索引二分 + 文件 seek，不从头扫。
- **预取**：翻页后在后台把后面 6 页排出来（`PrefetchManager`，单并行度，和主线程靠引擎的锁互斥）。
- **线程**：IO/排版/预取都不在 UI 线程；Compose 只拿"当前一页"，每行一次 `drawText`，一行都不是一个 Compose 节点。
- **测量边界**：`LineBreaker` 是接口——Android 用 `Paint.breakText` 真量（走 minikin 的 Unicode 断行表），
  JVM 测试用近似字宽模型，所以分页算法在没有设备时也能被数字否证。

## 缺点 / 没做


- **pdf / pptx 没有版式可调**：整页渲染、保留原件版面，所以阅读页那套字号 / 行距 / 边距 / 段首缩进 /
  纸色六档对它一概不生效，顶栏右侧因此明写了「原版面」。这一类只有三个动作：
  **翻页** = 点屏幕左右 1/3（分界数学和阅读页同一颗 `ReaderGestures.zoneOf`，core 里有判据；中间 1/3 收放上下两条栏，
  「点击两侧均翻到下一页」那棵开关也照读；没放大时还能左右滑）；**放大** = 双指在页面上张合，1.0~3.0 倍整页等比
  （形状、图片、表格、文字同一个比例），放大后单指拖着看局部（pdf 竖向仍走列表、ppt 的翻页滑动让给拖动）；
  **播放**（只 pptx，在抽屉顶行、「前往」左边那颗「播放 / 暂停」）= 一页一页往前放，速度那一排选
  `慢 12s / 中 8s / 快 4s`（点一档就开始放），走到最后一页自己停下、那颗按钮跟着回到「播放」。
  抽屉**就是这一类的底栏本身**：点屏幕中间把上下两条栏放出来，下面那条直接是它，不再"点页码再弹一层"。
  版式照他给的那张图：顶行左「取消」纯文字、右「前往」实心强调色（图里那颗「创建」），
  **中间那对分段控件没做**；下面圆角输入框（只收数字，占位「输入要跳到的页数」）+ 一行「第 N / M 页」。
  外壳和另外两个底部抽屉同一份规矩（顶上一对圆角走常量 `SHEET_RADIUS = 10dp`、空白自己吃点击、`imePadding` 让键盘抬起来）；
  「取消」和「前往」都先收键盘。原来那颗模态「跳页」框删了，底栏不再单独显示页码。
  pdf 正文的底部留白跟着抽屉自己量上来的高度走（`onHeight` 报上去），不写死一个数。
  抽屉和滑轨都撤了。**pptx 没有单独的"字号"旋钮**：定版面里形状框装不下时 PowerPoint 会先把字缩小以适应，
  用户倍数乘在它之下会被框顶死（真机量过：选 155% 时生效值反而掉到 31%、版面几乎没动 = 白按），乘在它之上又会盖出框外
  并把版面挤乱 —— 两害相权，放大整页是唯一入口。缩放/播放是这一屏的临时状态，不落库（没有"复位"那颗按钮了，
  存着一个 2.5 倍下次打开反而看不出为什么）。
  pdf 的位图只渲到 2 倍为止：一张 3 倍的 A4 是 3240x4583 = 59MB，会把按 `maxMemory/4` 的那格 LRU 挤得只装得下一页，
  而 2 倍时正文已经约 40px 高 —— 再往上只是摊大已有像素，不是多要细节（这条是算出来的，不是量出来的）。
  也**没有分栏**。夜间模式不反色 pdf（反色会把扫描件变成看不清的东西）。
- **pptx 只画文本框、图片和表格**：按形状自己的 EMU 位置等比铺到屏宽，run 级的粗体/斜体/字号/颜色都跟着；
  母版和幻灯片背景、SmartArt、图表、动画、演讲者备注都不画（`graphicFrame` 里只认 `a:tbl`）。`.ppt`（97 二进制）
  直接拒并回一句"另存成 .pptx 再导入"——这条分支手上没有 .ppt 样本可打，只按代码路径确认（它排在 txt 兜底之前，
  不会被当纯文本吞成乱码）。
- **mobi / azw3 只认「不压缩」和 PalmDOC LZ77**：HUFF/CDIC 压缩、DRM 加密的直接拒，并把原因写在回话里
  （这种书用 Calibre 转成 epub 再导入最快）。AZW3 是 MOBI6+KF8 双份，读的是它自带的 MOBI6 那一份：正文一样，标记老一点。
- **epub / docx 抽的是纯文本，不保留原书样式**：加粗、斜体、图片、脚注、原书自己的缩进都没了，章节靠正文里的标题行重新认。

- 元数据落 `manifest.kv` + 二进制索引，没用 Room。章节数上万后 `chapter.idx` 是一次读满的整表，够用但没做分页。
- 全文搜索是逐块 `indexOf`，没有倒排索引 / FTS5；千万字实测 39ms 所以先不做，但两亿字级别会撑不住。
- `仿真` 是"旧纸绕书脊立起 90°"的近似，不是真书页那种带弧面的翻卷（那要网格变形/着色器）；翻到中途能看到
  纸的侧棱，但不会出现卷起来的圆柱面。
- `上下`（滚动）跨章连续：窗口是"连续若干页段"（一段 ≤6 页，整段不跨章），离上下边缘一个半屏就补一段；
  往下补就把最上面那段剪掉、同时把滚动量同帧减去它的高度，往上补则剪掉最下面那段（那段在视野外，不用校正）。
  只剪"整段都在视野外"的，正在看的那段宁可暂时超预算也不剪。滚动位置仍然只存字符偏移，切回按页模式后位置不丢。
- 往回翻遇到只有几行的极短章，可能看到一次跳动（往前补那一刀依赖 `scrollTo` 不被旧 maxValue 夹住）。
- `上下` 那一档改字号后，游标还会退不到一行以内：`13|60914` 连改四次（17→19→17）读回 `13|60894`，退 20 字 = 同一行的行首（重排后这一行本来就从 60894 起）。再往前往后各滚一屏，位置不再动。
- `自动阅读` 做了，速度是三档「行/分钟」（12/24/48），上下和按页两种模式共用这个口径：
  上下那一档实测 63.6px/s，和 48 行/分 ÷ 79.5px 行高算出来的 63.6 完全吻合；按页那一档 39 行 ÷ 48 行/分 = 48.75 秒一页，
  实测约 50 秒一页。缺点：只有三档、不能无级调速；面板开着、弹「该休息」时它照跑不误（只有休息弹框会让一下）。
- 字体表只扫 `/system/fonts`（和 `/system/fonts/GMSFonts`）：用户自己装到 sdcard 的字体、以及需要下载的字体不在里面，
  也没有字体文件的导入入口。判"认不认识中文"用的是字体自己的 cmap，要求 `中/的/门` 三个字都有字形
  ——`MiSansC_3.005.ttf` 只有 35KB（是个子集），就这样被筛掉了。`.ttc` 要读第 0 个 face，
  而 ttcf 里每个 face 的表偏移是**整个文件的绝对偏移**，不是相对 face 头（读错会读到垃圾 format 号，整款字体被误判成"不认中文"）。
- `繁体转简体` 用平台自带的 ICU transliterator（`android.icu.text.Transliterator`，**API 29 起才有**，低版本那颗开关灰着）。
  K40 上量过：`風雲變色，誰知我劍來？` 32 字进 32 字出、15 个字被换掉；对本来就简体的正文是恒等变换（`changed=0`），
  所以简体书开着这颗开关，整页像素逐字节相同（唯一差异是状态栏的钟）。
  转换只在切正文时做，且**长度一变就整段退回原文**（页上的行是按源文偏移切的，见 `safeConvert`）。
  没验到的一步：手上没有能导入的繁体书（`file://` 走 VIEW 意图在这台机上读不到字节），
  所以"繁体书翻开后屏幕上真的变成简体字"这最后一格要人眼过一遍。
- `休息提醒` 只在这一页开着时计时，退到后台不计时。
- 亮度条改的是本窗口的 `screenBrightness`，不动系统亮度设置；`护眼模式` 是叠一层暖色，不是系统级滤光。
- 横屏、副屏、异形屏没量过（K40 竖屏验的）。状态栏/导航栏底色和图标明暗已经跟主题。
- 段落识别只认换行，不做首句加粗、诗词居中这类版式。
- 避头点只按一组常见标点位，没有完整行压缩规则；拉丁长词会硬断。
- 没有进度云同步、没有笔记导出、没有 TTS。
- 章节标题识别是启发式五条规则（第X章/节/回…、Chapter N、"1、…"、"001你到底是谁"这种裸编号、序章/番外等）。
  认错会让一章碎掉，所以配了三道兜底：含句末标点的行不算标题、短于 40 字的"章"吞进后一章、
  超过 20 万字的章在段落边界上切开（排版单元必须有界）。仍可能漏掉写法特殊的标题。
