# 界面与功能

> 从 README 拆出（2026-10-16）。安装与技术栈见根目录 README；开发过程记录见 ../开发记录.md。
> 下面的像素数和真机读数都是当时量一次留下的，改动后需重量。


界面（底部四个 tab：书架 / 精选 / 书签 / 我的；按 2026-10-08 你给的纵横截图版式改的外壳）：

   **底栏那条的底色 = 界面底色**（`Chrome.page`，日 `#F6F7F9` / 夜 `#121316`），和阅读页两条工具栏同一条规则：
   不单独开一档 bar 色，只靠顶上一条 1 物理像素发丝线分界；系统导航条也改成同一个 token（原先它铺的是卡片白，
   等于同一条栏两个主人）。外壳四页从此共用 `Chrome.page` 一个背景色。

1. **书架**：右上角三颗点 = 一个只有两行的弹框：第一行在**图墙 / 列表**两种排布之间换（文字按当前模式取反，
   图墙下写「切换至列表模式」，列表下写「切换至图墙模式」），第二行「本地导入」= 选本地书入库；
   选中的那种排布会记住（`shelfList`）。图墙 = 3 列卡片（卡片面用书名前两字占位，没有封面图就不放假图），
   末尾多一颗虚线「添加作品」；列表 = 一行一本，左边小封面 + 右边三行（书名 / 作者 · 读到哪 / 章数 · 字数），
   卡片外壳和封面尺寸跟「精选」那一行同一份。能开的格式：**txt**（UTF-8 / GB18030 自动判）、
   **epub**、**docx**、**mobi / azw3**（PalmDOC LZ77）、**markdown** —— 这五种都是抽出正文喂给同一个排版器，字号、行距、
   边距、纸色六档、翻页、书签、搜索全都有（markdown 额外带一层样式，见下面「开 md」那行）；
   **pdf** 和 **pptx** 走另一条路（整页渲染、保留原版面：翻页点屏幕左右 1/3，放大**双指在页面上张合**，
   点屏幕中间放出来的**下面那条栏就是抽屉** —— 跳页输入框 + 「前往」，pptx 还有「播放」和速度，见「缺点」）。
   进度显示在顶上；抽不出正文的（DRM 加密、HUFF/CDIC 压缩）回一句人话说明为什么，不会当成 txt 吞进去。
   长按一张卡片 = 删这本书（二次确认是**从底部推上来的抽屉**，和「偏好设置」那颗同一份 `ModalBottomSheet` 外壳；
   只删入库副本，原文件不动）。
2. **精选**：**静态样例页**，版式和图都按你给的参考截图量着做（封面 61x82dp、左边距 19dp、图文间距 12dp、
   行距 97dp；实测我们这边封面高 226px/参考 225、行距 264px/参考 266）。这一页原来是整屏纯白（唯一一个不跟
   界面底色的页面），现在跟其余三页同底色，列表**做成卡片** —— 外壳照书签那一档同一份（卡外缩进 12dp、
   圆角 10dp、卡缝 10dp、卡面 `Chrome.card`），封面左缘还是 19dp：拆成"卡外 12 + 卡内 7"，做成卡片不该把内容挪位。
   代价是行距从 97dp 变成 97+10=107dp（多了那道卡缝），这一处**还没在屏幕上复量**。六本书的标题、简介、分类、标签和封面
   **全部是从截图里抄/裁的样例数据**，点一行只会在顶上回一句"书源未接入，加不了书架"。上线前必须整块换掉。
   **长按正文选中整段**（按页和上下两档都行）：选中那一段铺一层墨色 18% 的底，屏幕下面浮出动作栏 ——
   图标在上、文字在下、一行五颗：`评论 听书 词典 纠错 书签`。**动作栏贴在选中段落的上面**，
   只有选的是第一段（上面放不下）才落到下面；**不画边框，靠底色浮起来**（用面板那颗 `bar` 色，六档各有对应色）。
   **选中底色铺到两端对齐后的右边界**：字距拉开后一行实际占宽 = natural + 字数×tracking，
   原来按量出来的 natural 铺，右边就缺一截（他圈出来的那条）。量过：选中行底色右到 **x=997**
   = 版心右边界 1080-82.5（正文墨迹 86..994）。**加过书签的段落下面画红色波浪线**（`drawLines` 里逐行
   画 quad 曲线，整段每一行都标，宽度用同一个 `drawnWidthPx`）：点完书签 `marks` 立刻重算，波浪线当场出现，
   收起选中后还在。当场量过：长按后底栏区变化 14875px、正文区
   （选中底色）52371px；点正文或按返回键收起后再截一张，**与未选中时逐像素相同（0px 差）**。
   五颗里 **书签是真做**（点一下存档从 `marks = 2|5874;13|59237` 变成 `...;13|60780`，记的是这一段开头的偏移）；
   **听书接系统 TTS**，这台 K40 没装中文语音引擎，所以它回一句「这台机没有可用的中文语音引擎」
   （引擎还在启动时会回另一句，不含糊过去）；**词典接的是你自己配的 AI**（见下面「AI 翻译」），
   没配的时候点它回一句"还没配 AI 翻译：我的 → AI 翻译…"，配了就把选中那段的拼音 / 释义 / 译文回在底部面板里；
   **评论 / 纠错没有后端**，点下去只回一句缺什么，不装成能用。
3. **书签**：跨书的标记列表，每条显示书名、章名、第几字和那一行开头的正文；点一条 = 把那本书的位置设成它并直接打开；
   右侧「删」删掉这一条。
4. **我的**：真数（N 本 / 已入库字数 / 已读字数）、导入入口、阅读配色三档、清除全部书籍（红色，二次确认）、关于。
   其中两行是 **AI 翻译** 和 **AI 听书**（右侧各写「未配置 / 已配置」；2026-10-13 从原先那一格「AI 服务」拆成两格两屏），
   点进去各是**另开的一整屏**、不是弹窗 —— 顶栏 `‹ AI 翻译 …… 保存` / `‹ AI 听书 …… 保存`。
   **AI 翻译**那一屏一张卡片三格（API 地址 / 模型名 / 秘钥，秘钥默认打点、旁边一颗「显示 / 隐藏」，
   存过之后那一格留空表示"不改"，屏幕上从不回显已存的秘钥），下面「试一下」发一条最小请求把结果回在旁边。
   地址填 `https://x/v1`、`https://x/v1/`、`https://x` 都会被归一成
   `https://x/v1/chat/completions`（已经填到底的不重复拼）；填 `http://` 时地址下面会红字标出"明文走网络"。
   **AI 听书**那一屏先三选一挑服务商（OpenAI 兼容 / MiniMax / 阿里 Qwen-TTS，选完下面各格的示例文字会跟着换），
   再填 语音地址 / 语音模型 / 音色 / 可选音色 / 语音秘钥 + 两颗「拉音色列表」「试听」（试听合成一句固定的试听词，播着时那颗变「停止」）。
   两屏**各存各的**：对话地址和语音地址可以完全不同，秘钥也各存一份；**在一屏按「保存」不碰另一屏那几个键**
   （`save()` 按那一屏验、按那一屏写；真机：听书屏按一次保存，`aiBaseUrl / aiModel / aiKeyCipher` 和 `aiVoice*` 逐字节未变）。
   底下那几行规则说明也只写这一档的事，不再两半混在一页。
   另有一张单独的卡三行：**皮肤管理 / 字体管理 / 菜单管理**（各开一整屏，`‹ 标题`，**没有「保存」**——
   这几页每一下都当场落盘并立刻生效）：
   - **皮肤管理**：`OpenDocument` 选一张图 → 拷进 `filesDir/theme/bg.<ext>`（只存文件名，SAF 那条 uri 的读权限会被收回）→
     只铺在**小说正文那一屏**，图上压一层**当前那档纸色**，浓淡一颗滑块（`bgDim`，默认 0.82）。
     正文那一层（`PageView` / `ScrollReader`）在有图时改画透明，纸色由下面那层出 —— 不然图被自己的纸盖住。
     解码按屏宽 `inSampleSize` 缩（一张 4000x3000 整张进内存是 48MB），预览和正文共用同一份解码。
   - **字体管理**：全局字体（ttf/otf/ttc，`Typeface.Builder` 解不开就明说「那个文件不是一支字体」，不会半换）
     + 全局字号四档（0.85 / 1 / 1.15 / 1.3）。字体挂在 `TipHost` 的 `LocalTextStyle` 上发到整只 app；
     字号挂同一层的 `LocalDensity.fontScale`，**而阅读正文只认系统 fontScale**（`ReaderScreen` 读 `LocalConfiguration`），
     所以两档各算各的。真机：外壳标题墨高 56 → 65px（+16% ≈ 那颗 1.15）、收回 56；正文**三档下都是 33 行 / 行周期 55px 逐位相同**。
   - **菜单管理**：两颗开关「显示 搜书」「显示 精选」（这两格的内容都是从书源装回来的），写 `hiddenTabs`，
     底栏按它筛 —— 真机：藏掉精选 5 格 → 4 格、开回来 → 5 格。书架 / 书签 / 我的 不给藏（藏了就没有回到这一页的路）。
   - **全屏模式**在「我的 → 偏好设置」那颗开关里（写 `fullScreen`）：**只在"这一本挂了背景图"的那一屏阅读界面生效**
     （他第三轮点名的口径 —— 没有背景图的书、漫画 / pdf / pptx 三屏一律不藏系统栏，藏了只是把一块实心纸顶到上沿，
     换不来任何东西）。判据 = `prefs.fullScreen && bgFile != null && 自己的上下栏和抽屉全收`。
     生效时把系统状态栏和底部导航条也盖过去（`ApplySystemBars` 里那一个
     `WindowInsetsControllerCompat`：`hide(systemBars())` + `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`），
     栏一亮起来、或离开这一屏就 `show()` 还回去。
     判据和音量键那一串是同一份层表 —— 顶着状态栏画我们那条栏就是两层叠在一起。
     **文字排版不跟着动**（他第二轮点名的口径："只是背景撑满状态栏和导航栏"）：`safeDrawingPadding()` 读的是
     **当前** insets，栏一藏就变 0，正文会整块往上/下挪、同一章从 6 页变 5 页 —— 那就不叫"只换背景"。
     所以藏栏那一态改走 `fixedBarsPadding()`（`ApplySystemBars.kt`：`getInsetsIgnoringVisibility(systemBars ∪ displayCutout)`，
     藏与不藏给出**同一个数**）。
     **三层各管一件事**（他第三轮贴回来的图就是这三层没分层：我们那两条栏压在系统栏上）：
     ① 最外一格 `fillMaxSize().background(纸色)` —— 整块窗口的底，系统栏背后那条就是它（实心纸色）；
     ② 背景图那一格**永远铺满整块窗口**（`fillMaxSize`，高度不随藏栏变）—— **菜单亮着的时候，状态栏 / 导航条那两条
     用实心纸色直接盖住图**（盖，不是让位：`systemBarHeights()` 取"藏了栏也不变"那一份高度画两条实心带）；
     菜单收下去，那两条盖条撤掉，图就露到边上。原来这一层自己 `safeDrawingPadding()` 让开系统栏，
     栏一收它整块跳上去 84px —— **那就是他看到的闪烁**；
     ③ 正文 + 我们自己那两条栏那一格用**冻住**的那一份（`fixedBarsPadding()`，`insetsIgnoringVisibility`）——
     所以栏的位置和从前逐位相同、收放那一下正文不跳。②不读活 insets、③用冻值：没有任何一层的高度会变。
     ④ 藏/还系统栏和图标明暗走**同一个主人**（`ApplySystemBars(darkIcons, immersive)` 那一个 `SideEffect`），
     而且**只在真的换了档那一刻**才 `hide()/show()` —— `SideEffect` 每次重组都跑，无条件发显示/隐藏请求
     本身就是叠在一起的动画（另一半闪烁）。另起一处 `DisposableEffect` 做 hide 也不行：
     `ApplySystemBars` 每次重组新建 controller 会把它顶回去（现象是"全屏没生效"）。
     ⑤ **过渡对齐的是"什么时候结束"**（他连点三轮：先是"过渡时间和菜单栏一样"，选了"菜单跟着系统栏走"，
     再点出"是**隐藏**的时候不一致，出现一样了"）：
     出现那一向我们 tween(275)、平台报 311ms，两个几乎同刻结束 → 他认这一向；藏那一向他原来 275ms 就收干净了，
     状态栏那点墨还在屏上停着 → 就是"不一致"。
     平台回调那一头的数（临时往 `onProgress` 里打 logcat 量的，量完已撤）：`prepare` 报 **1500ms**，
     整段 96 条回调里 **`interpolatedFraction` 一直是 0.0、insets 一路停在 84/130**，只在最后一条才跳到 0 ——
     照它给的数走 = 憋满 1.5 秒再啪一下，我们反而**慢** 580ms。图标那一段是 SystemUI 自己画的，回调里量不到。
     **录屏的 pts 钟不能用**（`r_frame_rate` 报 90000/1、ffmpeg 抱怨 dts 非单调、开头空 750ms），
     拿它换算出过互相打架的两个比例（0.69 倍和 1.38 倍），所以只留**同一张帧网格上各占几帧**这种和尺度无关的数。
     锚点 = 我们那条淡出在屏上开始掉的帧（底带 y2270..2400 整宽均值，Δ15.5 级、够分辨；顶带只有 Δ6.8 级，
     纸色 254 对压淡的图 248，那条尺子定不住自己的终点 —— 这就是"我们那条曲线"原来量不干净的原因）。
     三档系数各量三趟（我们淡出占的帧数 / 图标墨归 0 时占的帧数）：
     **0.62（命令 930ms）40 / 55 早收 15 帧；0.85（1275ms）55·60·51 / 52·55·47 晚收 3~5 帧；
     0.78（1170ms）48·54·48 / 53·59·52 早收 4~5 帧** → 两个因子对系数插值到 1.0 = **0.82**。
     装上 0.82（命令 1230ms）之后四趟：**54/52、49/47、49/51、54/52 帧** —— 差 ±2 帧，
     因子在 0.96 和 1.04 之间来回，已经在这把尺子的趟间散布（±3 帧）里，再往下抠就是抠仪表的噪声了。
     导航那一条本来就快：底部那 130px 的暗墨在发枪后两帧就归 0（它不像状态栏那样压着走）。**还是让它和上面同一条
     淡出走** —— 整只菜单一次动作，比"上面 1.2 秒、下面 0.27 秒"两条不相干的动线好读；
     而导航没了之后那段尾巴是纸色 254.8 → 图 239.3 的**逐帧 0.3 级**溶解（15.5 级摊到 52 帧），
     比这把尺子自己的噪声（±1 级）还小，屏上看不出"有一块东西还赖着"。要真想让下沿跟着导航一起清，
     就把 `menu`/`band` 拆回两条（上面那条 0.82、下面那条 275ms），一行判据的事。
     时长仍然从平台回调里学（`Chrome.barHideMs` / `barShowMs`），不写死；只认我们自己刚发出去那一枪，
     键盘的 IME 动画不算（`pending` 那一对冲淡标记）。
     `window_animation_scale`、`transition_animation_scale`、`animator_duration_scale` 三个都是 1.0 —— 那些数没被放大。
     **系统栏那条动画可以接到应用手里**（这才是"隐藏速度能不能调"的正解 —— 手机上没有只调系统栏隐藏速度的
     开关，开发者选项那三个缩放是全屏幕的）：compat 有 `WindowInsetsControllerCompat.controlWindowInsetsAnimation(
     types, durationMillis, interpolator, cancellationSignal, listener)`，**时长是参数**；`onReady` 里逐帧
     `WindowInsetsAnimationControllerCompat.setInsetsAndAlpha(insets, alpha, fraction)`，走完 `finish(false)`。
     （我早先记的"compat 不给 `setProgress`、签名对不上"是**找错了名字**：这版 core 1.18 里没有 `setProgress`，
     叫 `setInsetsAndAlpha`；`Insets` 也没有 `lerp`，四边自己插。签名是从 class 里 + 编译器报的候选抄准的。）
     **只有"藏"这一向接**：上一版两向都接，这台 MIUI 在"还回来"那一向不认我们报回去的 alpha，
     栏就停在藏那一态（他截图量到：菜单开着、图标墨 0 / 时钟墨 0 / 导航墨 0）→ 那条已经退回走系统 `show()`。
     **这一条还没在屏上量过**：欠两笔 —— ① 接管成没成（`Chrome.barsSynced`）+ 图标墨归 0 和我们那条淡出
     是不是同一帧；② 开菜单时栏还回得来回不回（上次就是这条办坏的）。量不出来之前，0.82 那档拟合还在原地兜着。
     ⑥ **淡出这一路那两条栏不能再当菜单点**（时长从 275ms 拉到 1.2 秒带出来的副作用）：栏在淡的时候还在组合里，
     命中窗口原本跟着那条曲线走，就成了"收了菜单还点得到栏"。`Modifier.fadingTap(bars)`（`ReaderScreen` 文件尾）
     把命中窗口钉回 `bars`：**这一枪在 Initial pass 就消费掉**，抬指时位移没过 touchSlop 再按正文判据补发一次。
     **第一版挂的是父层 `detectTapGestures`，真机一枪就打回书架了** —— Main 那一轮孩子是先到事件的，
     父层拦不住 `BackChevron` 自己的 clickable；Initial 的消费才会带到后面每一轮。
     （`Modifier.enabled` 在这台的 Compose 1.12.1 里**没有**这个扩展，类表里查不到，别照着新版文档抄。）
     真机（`scratch/fadingtap.py`）：收菜单后 150ms 点左上角「返回」那一格 `(39,118,94,173)` ——
     **没有退出阅读屏**（判据是树里出不出「书架 / N 本」那两颗字；不能用「N/M 页」，那颗本来就在栏里、
     菜单一收就不在树上了），再一枪中间把菜单开回来 = 亮着的时候那一层一个字都没接。
     **他的位置没被挪走**：出发时 第1章 永夜 1/4 页，测完回读还是 1/4（多翻的那一页退回去的）。
     真机（右上角电池那一小格 + 左上角时钟那一小格的墨数，正文左右版心到不了那两格）：
     上下栏亮 480/386 → **上下栏收 0/0** → 再放回来 493/361

### 搜书（底栏第五格）

一条**书籍源** = 一个 JSON 文件（`filesDir/booksource/*.json`）：导入即装上，删掉即卸载。
页面形状：上面那排选源（坏的那条灰着，点它会说为什么坏）→ 输书名 → 结果列表 →
每行右边那颗按状态换字（「下载」→ `137 / 3206 章` → 「打开」/「重试」）。抓完直接进书架，
和本地导入进来的书没有区别。

源文件的字段和取值语法在 `booksource/README.md`。两类源**导入时就拒**并说明原因：要跑 JavaScript 的
（手机上不内嵌 V8）、Cloudflare 盾的。

随包**九条**源：三条小说（梦书中文、爱下书小说网、书海阁〔一章切几页的那家〕）+ 两条漫画 + 两条文献 + 两条有声（公开播客 RSS、古文岛·古籍有声），
可关可删，删了不自愈，「恢复随包」那颗能按包里那份换回来。
引擎在 `:booksource`（纯 JVM、可拔掉；离线判据 + 打在**真站抓回来的页面**上的那批，含正文页和漫画页）；
联网、落盘、入库那三段在 `:app`。别的站没随包的原因写在 `booksource/README.md` 里。

### 一条源是小说、漫画、有声还是文献（`kind`）

源文件多了一格 `kind`：`novel`（默认，不写就是它）/ `comic` / `audio` / `paper`。它决定三件事：

- **一条源是哪一族，标在源那一排的 chip 名字上**：`图库漫画·漫画`、`arXiv·文献`、`某某听书·有声`，
  小说不标（它是默认，每颗都带「·小说」等于都没带）。这条是"搜索页面也提供漫画的地址"的落点 ——
  入口就在选源那一排本身，不另起一行 tab 去筛（那一行先做过、他点名撤了），也不藏在管理页里。
- **下载抓什么**：小说抽文字、漫画抽每一章那一排图、有声抽每一集那一段音频、文献直接下那支 PDF。
- **精选那一排的「漫画」/「有声」tab**：`kind=comic`/`audio` 的源抓回的热门，类名一律改成那一类，
  不拿站点的"热血 / 冒险 / 恋爱"、"都市 / 推理"去撞小说那六类（撞不上，表现就是那颗 tab 永远是空的）。

管理页只列源本身（类别不在那里说第二遍 —— 同一件事不留两个主人）。

### 漫画

随包两条，都是**从这台机取回真页面判过**的（判据在 `:booksource` 的 `ComicPaperFixturesTest`，
`live/` 那批夹具不进仓库，所以新克隆的机器上这几条按跳过算）：

| 源 | 实测 |
| --- | --- |
| 图库漫画 tuku.cc | 搜「魔法」21 行；书页一次给全 435 话；那一话写着 28P，`chapter.image` 就抽出 28 张；图床查防盗链 —— 不带 Referer **403**，带章页自己 **200 / 131,767 字节的 JPEG**（980x1403） |
| 瓜子漫画 guazimanhua.com | 搜「斗罗大陆」7 行；海贼王书页整页 2148 条章链接，`toc.item` 只认 `div.all-chapter-grid` 那一格 = **1068 条不重复**；章页 105 张图在 `src` 里；图床不查 Referer、地址不带签名；目录是 newest-first，靠 `toc.reverse` 翻回阅读顺序 |

一条漫画 = 一章一排图，所以它**不进排版引擎**：`BookMeta.COMIC` 和 pdf/pptx 同一族（清单里没有 chunk/章索引），
图落在 `filesDir/books/<id>/comic/<章地址 sha1>/`，里面一份 `pages.tsv`（一行一个图片地址，行序就是页序）
+ 按地址 sha1 命名的那些图。键用地址不用序号：站点补一章或把页序动了，按序号存的会张冠李戴。

读它的是 `ComicReaderScreen`：**一屏一张，点哪翻哪页和小说同一套**（`ReaderGestures.zoneOf` 三个区，
左右 1/3 上/下一页、中间收放栏；走到本章头一张再点左退到上一话的最后一张）。
**横向甩也翻，而且甩到头同样跨话**：末页往左甩进下一话第 1 张、头一张往右甩退到上一话最后一张
（2026-10-13 真机，银之守墓人：`7|9 → 8|0 → 7|9 → 8|0`，章中甩 `7|6 → 7|7` 照旧归 pager 自己滚）。
这一条挂在外层 `PointerEventPass.Initial` 上、全程不 consume，位移要过屏宽 1/3 且明显偏横才算。
底栏就是小说那一排四颗 **目录 / 书签 / 夜间 / 设置**，设置里只留两行：**亮度**（滑轨 + 跟随系统那颗，照抄小说那一整行）
和 **背景**（那六个色块，写的是同一个 `themeIndex`，所以外壳的夜间跟着一起变）。
目录是**从左边推满高度的抽屉**（300dp、右缘 16dp 圆角、`theme.barColor`），每行行首一颗
该章**第一页的小缩略图**（20×28dp，解码走 IO 并进那格 LruCache），没下的那几行灰着、点了说为什么。
书签存「第几话 + 第几页」（`comicMarks.<id>`），「记当前页」在那一层顶上。
进度也是这一对（`comic.<id>`）：每话有几张图只有磁盘上知道，压成一个数就得在每个读它的地方各除一次。
**没有长条那一档了**（撤它是因为底栏只留那四颗，那一颗开关放不下；要回来的话得说他要点在哪）。

漫画**必须先下载到本机才能读**：这两家的图片地址都带签名（`key=` / `hkey=` / `t=` 那一种），
过一会儿就失效，边滑边取等于每翻一页再打一次站子。这一点和小说不同。

### 有声书

**引擎、播放器都做完了，随包两条能用的源**：喜马拉雅**公开分发**的播客 RSS，和古文岛那种**一回一支整回音频 + 同一页正文**的古籍有声。
它已经在随包名单里（`podcast-rss`，`files/booksource/` 种一次），管理页那颗「恢复随包」也管着它。

能用的道理很具体：RSS 是播客行业的分发契约，Apple 的抓取器就是我们同款纯 HTTP 客户端，
所以站点必须让裸请求拿到字节。2026-10-14 在**两侧各打过同一支文件**：

| 从哪打 | 实测 |
| --- | --- |
| PC 上跑真 `HttpFetcher` + 真 `AudioDownloader`（整条链） | 搜「西游记」出 **9 本**（每条都带 `feedUrl`）→ 挑《百度西游记》那份 RSS **整本 105 集**、一次给全不用分页 → `head=2` 落地 **6,730,497 字节**（3,787,944 + 2,942,553），两集开头都是 `00 00 00 1c 66 74 79 70 4d 34 41 20` = `ftyp` + `M4A ` |
| 手机自己的 curl，应用外（同一条地址） | **200 / 3,787,944 字节 / `audio/mp4`**，开头逐位相同 |

断点顺手也验了：第二遍跑的时候第一集一个请求都不发。

第二条 `gushiwen-audio`（古文岛·古籍有声）走的是完全不同的一族：章回小说和史部，**一回一条目录、
一回一支整回 mp3，而且正文就在这同一页上**（所以它是"文字跟着读"那一格唯一的来源，见下一节）。
它没有 `search`（站内搜索 302 到登录页），入口在「精选 → 有声」那一档；音频地址写成
`href="javascript:PlayBookv(9801,'id','https://….mp3',…)"`，引擎为此加了 `@href@url` 那一档取值后缀
—— 正则从参数串里抠出第一个 http 地址，**不跑 JS**（判据 `AudioTest.urlSuffixPullsTheAddressOutOfAJavaScriptParameterString`）。
真站复验的数：精选 10 本 → 红楼页目录 **120 回整本一页给全** → 第一回 **36,357,164 字节**、开头 `49 44 33 04` = ID3、
同一页正文 67 段 / 非空白 7768 格，一起落进那一集的 `text.txt`。

这条源要的三个新格（写法与理由见 `booksource/README.md`）：`toc.format="xml"`（书页是 RSS，和 JSON 的搜索口不是一种东西）、
`toc.href="enclosure @url"`（地址不挂在 `<a href>` 上）、`chapter.audio="@self"`（目录里那一条地址本身就是文件，
**一次集页请求都不发**，Referer 改发书页）。三格各有一条判据，`toc.format` 那条是反证：漏写不报错，
集名会带着 `<![CDATA[…]]>` 两层壳进界面。

另一条走"自家 CDN + 签名"的路（恋听网 ting55）**不能用**，今天复现过两遍（脚本 `scratch/ting55-audio-probe.sh`，不进仓库）：

| 步 | 实测 |
| --- | --- |
| 搜索 `ting55.com/s/斗破苍穹` | **200 / 3,939 字节** JSON，第一条 `id:701`、`transmit:"桑梓"`（播讲人） |
| 集页 `/book/701-1` | **200 / 5,368 字节**，取址要的几个 token 都在 meta 里：`_c=e3c0e5fb…`、`_l=1`、`_b=701`、`_cp=1`、`_m=1208`、`_f=mp3` |
| `POST /nlinka`（带 `xt` + `l` + `X-Requested-With`） | **200 / 127 字节**、`status:1`、签名地址 `pp.ting55.com/202610142033/…/701/1.mp3`（路径里那截就是刚生成的分钟戳） |
| 要那支 mp3 的字节 | **404**。浏览器 UA + Referer 一套、`Accept/Sec-Fetch-*/Origin` + cookie 罐一套、裸 curl 一套、`?v=<毫秒戳>`（浏览器 JS 补的那一颗）加上与不加、GET 和 HEAD —— 五种打法**全部 404**，回的是 651~676 字节的 `text/html` |

签名地址是新的（分钟戳对得上），所以 404 不是过期，是这一家的 CDN 只把字节交给浏览器自己的播放栈。
其余探过的也都各有拦不住的原因：要靠 JS 挑战才给目录的（pingshu8）、整站是 SPA 的（听书 / 天方听书）、
接口已下的（喜马拉雅的 revision 接口 404）、文件挂在连不通的主机上的（LibriVox 的音频在 archive.org，
这台机那个主机超时）、以及十来家已经打不开的。这一族的结论和「文献」那一条一样：**做不出的就不摆那颗按钮**，
免得进度走到 100%、抓回一本空的。

所以这一档现在是**给导入用的**：手上有能直下音频的站（页面里 `<audio>` / `source` 的地址浏览器不给就 403 那种不算），
写 `"kind": "audio"` + `"chapter": { "audio": "audio source @src" }` 装进「搜书 → 管理书籍源」就能走通，
写法见 `booksource/README.md`。

做出来的是这些（判据全离线，夹具在手写页面上，一共 16 条：`:booksource` 的 `AudioTest` 9 条 + `:app` 的 `AudioBookTest` 7 条）：

- **抓**：`AudioDownloader` 和漫画同一族 —— 限速是全局累加槽位、重试到 `maxAttempts`、并发按 `crawl.concurrency`、
  断点靠"这一段的地址散列在不在盘上"。落盘 `filesDir/books/<id>/audio/<集地址 sha1>/parts.tsv` + 按地址 sha1 命名的段。
  开抓之前先写空清单和来源记录，所以抓到一半进程被杀，那一本还在架上、还认得同一个 id，下次点是接着补。
- **两道字节闸**：小于 4KB、或开头不是 ID3 / MPEG 帧同步 / `ftyp` / `OggS` / `fLaC` / `RIFF…WAVE` 之一，都算这次没抓到。
  要拦的是"会话被踢时回 200 的一张 HTML 登录页"——状态码看着是成的，存下来就是**每集都下到了、一集都放不出**。
- **一集的成败按真落地的段数算**：地址写着三段、只到两段，整集记进缺集。断在半截的一集播到一半就停，
  比缺一集更难发现；下次进来已有的段一个请求都不发（这条是判据写出来后当场抓到的缺陷，见 `AudioTest.resumeSkipsPartsAlreadyStored`）。
- **听**：`AudioReaderScreen` 是一屏播放器（封面 + 集名 + 一条进度 + ⏮⏯⏭），复用听书（TTS）那台 `AiVoicePlayer`，
  不另起一个主人。段放完接下一段、集放完进下一集；
  目录是从左边推满高度的抽屉（300dp、右缘 16dp 圆角，当前那一行只把字染成强调色），没下的那几行灰着、点了说为什么。
- **底栏就是阅读页那一颗**（2026-10-14 他点名"这个放到菜单里面去，而且要和阅读的菜单一样"）：
  同一份 `ReaderBottomBar`，四颗 **目录 / 语速 / 夜间 / 设置**，图标在上文字在下、58dp、顶部一条发丝线，
  和小说/漫画逐位同源。为此给那颗共用件加了两个带默认值的参数（第二颗的名字和图标）——
  有声这一族没有"第几页"可记，那一格空着就是颗死控件，所以给它当「语速」（图标沿用听书那页的 `ic_speed`，
  标签写成「语速1.0x」和听书同一口径）。「语速」点开是一排五档（0.75/1.0/1.25/1.5/2.0x，选一档立刻套到当前这段，
  存在 `audioRate`）；「设置」点开的是**漫画那一屏同一格**（亮度整行 + 背景六块，
  抽成了 `BrightnessBackgroundPanel`，两屏共用一份实现，不是各写一遍）。
- **翻开一屏不出声**（他点名的第二条）：进这一屏只把第一段 `prepare` 好并 seek 到断点，
  时长和进度条都是真的，但要点中间那颗才开口。`wantPlay` 一旦按过就一直为真，之后跨段/跨集才自动续放；
  从目录里点一集算"要听这一集"，也会把它写上。
- **暂停走显式 `pause()`**（他报的第三条 bug：按了暂停声音照旧）：`AiVoicePlayer.toggle()` 停下来之后还会
  顺手塞一个 0 倍速，而 `setSpeed` 在部分机型上会把播放器又顶起来。这一屏改用新加的 `pause()/resume()` 一对，
  不碰 `toggle()` —— 听书那一屏的 toggle 行为他已认可，不在这一次里跟着改。
  **这一条还没在屏上量过**：量法是"按暂停后 3 秒，`audio.<id>` 里那个毫秒数不该再涨"。
- **点空白收层**（2026-10-14 他点名的第三条）：开着目录 / 语速 / 设置任何一层时，点到它外面任何一处都**先收这一层**，
  和漫画那一屏同一条口径；层自己那一格吃点击（`consumesPanelTaps` / `PanelShell`），所以点在层里的空白处不会顺手把它关掉。
- **进度**：`audio.<id>` = 「第几集|第几毫秒」，每秒落一次表、退出和暂停时也落。
  账面那一格有声书和漫画分开：漫画数张，有声数**字节**（书架那一行写「240 集 · 1.18GB」，不写"0 字"）。
- 「先听一集」= 只拉目录第一集（音频一集几十 MB，小说那一条的"先拉开头十章"在这里等于一次要几个 GB）。
- **音量键在这一屏不接翻页**：听的时候那两颗该管的就是系统音量，和另外三族不一样。

#### 文字跟着读（只有"音频和正文在同一页"那一族有）

`gushiwen-audio`（古文岛·古籍有声，随包第九条）那一族一回 = 一整页正文 + 一支整回 mp3，抓一集时**同一页两样一起落**
（那一集的 `text.txt`，见 `AudioStore.putText`）。有正文的那一集，中间那一格从封面换成**整回正文**：

- 当前那一句染成强调色（和目录抽屉"当前那一行"同一口径，不加底色框）；
- **跟随只在当前那句滚出屏幕时才动**：一屏装得下二十来句，跟着每句滚等于每隔几秒整屏跳一下；
  而"跟着段滚"在这一族更糟 —— 古文岛一段能有 700 多字，滚到段首之后红字还在屏幕外面；
- 自己往上滚过，跟随就停下，右下角出来一颗「回到当前」；
- **正文上什么都不挂点击**（2026-10-15 他点名"这个点击屏幕中心不要翻页"）：点屏幕正中在这一屏仍是
  收放上下那两条栏。之前给每一段挂了"点到哪段听哪段"，实测一次中心点击把播放从 7:45 拽回 7:35；
  要跳有底下那条进度条，不该在正文里埋一颗看不见的按钮；
- 顶栏那条「正文 / 封面」只在有正文的那一集出现，没正文那一族连这颗都不摆（不摆死控件）；
- 字号走阅读正文那一档（`fontSizeSp`，和小说正文同一口径），主题/夜间跟着这一屏那条一起换。
- **这一屏也铺「我的 → 皮肤管理」那张背景图**（和阅读屏、听书页共用一份 `PaperBackground`：图铺满整块窗口 →
  压一层当前纸色，浓淡仍是那一格的滑块）。图铺在安全区**外面**，所以状态栏和导航条底下也是图。
- **正文上下各留 20dp 的缝，开在滚动视口上**（不是 `contentPadding`——那个只在滚到顶/底那一头才生效，
  中途滚动照样把一行字切一半），左右同一条 20dp；边缘那半行再淡出 8dp，是淡出去不是切一刀
  （淡出和听书页那个两行窗口共用一份 `edgeFade`）。
- **菜单亮着的时候，状态栏和导航条那两条盖成实心纸**（和阅读屏同一条口径、同一份 `BarPaper`）；
  菜单收起来时才让背景图透到那两条底下。

**时刻是估出来的，不是站点给的**：站点只给整回一支音频，页面上没有 `.lrc`/`.srt`/时间戳任何一样。
估法 = 按字数线性分摊到这一回的时长、每回开头归零（`FollowAlign`）。量过的数与两把尺子的读数写在
`FollowAlign` 顶上那段注释里，一句话版：跨回速率展幅 8.5%（所以必须每回归零，不然第 40 回到回末差 97 秒），
回内漂移在几秒这一档、不超过一句的长度。

### 文献 / 论文

随包**两条开放接口**，都不密钥、都免登录：

| 源 | 实测 |
| --- | --- |
| arXiv | 官方 Atom 接口（`search.format=xml`）。`arxiv.org/pdf/2010.11929` 直下 **3,743,814 字节**、开头 `%PDF-1.5` |
| OpenAlex | 开放文献索引（`search.format=json`，取值是点号路径）。搜「attention mechanism」限定开放获取 = 528 万条；25 条里 22 条带 `best_oa_location.pdf_url`，实下 11 支里 **10 支真是 `%PDF`**（那支 Springer 的 2,871,029 字节） |

下回来就是一支标准 PDF，所以**没有第三种阅读器** —— 开的是现成的整页那一套（翻页、双指缩放、缩略图、页码书签）。
`PaperImport` 只认开头那五个字节 `%PDF-`：不是就当场写明"这一条回的不是 PDF，回了 N 字节、开头是「…」"，
不把一张"要登录"的 HTML 存进书架变成一篇点开打不开的假文献。

没进来的：DOAJ 102 条 link 里只有 15 条看着像直接可下的 PDF、实下 12 支里 7 支真是 PDF（十个下载要失败三个）；
Semantic Scholar 在这台机 12 次里 11 次 **429**，唯一成功那次的 `openAccessPdf.url` 还是空的；
CORE 的下载口被 Cloudflare 挡；Europe PMC 走 EBI 镜像只给 `fullTextXML`、PDF 那一路 403；
**知网 / 万方要机构账号**，接口这一族做不到 —— 只能给你网页地址，点了走浏览器。

### 第二次点同一本书 = 增量

判据是"同一条源 + 同一个书页地址在架上有没有那本"，而**认的是书架上那本的 `source.tsv`**，
不是下载表那张可以删掉的行。找得回来就写回同一个 id（进度 / 书签 / 置顶全按 id 记，换 id 等于把人读到的位置抹掉），
只补目录里新增的章；已经抓到的章/图在磁盘上，一个请求都不发。界面上那颗按钮也跟着改字：
架上有了就给「打开来读 / 增量更新」，不再给「下载 / 先拉开头」—— 后者对架上那本会把整本重灌成开头十章。
