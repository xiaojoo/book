# 缺点 / 没做

> 从 README 拆出（2026-10-16）。已知缺陷、没走到的验收、以及刻意没做的部分。

- **皮肤管理和字体管理那两条"选文件"的口子还没在真机上走过一次**（2026-10-13 23:0x）：
  `OpenDocument` 开起来之后前台被他自己另一个 app 抢走，那两枪落点没法自证，我当场停手。
  已经量到的是这三屏的**界面和效果**（三行都在、藏/开底栏 5↔4 格、全局字号 56→65px 而正文 33 行/55px 不动）；
  **已经量到的一半**（K40，2026-10-15 真机截图）：挑一张图之后**正文底下确实透出图来**（`bg.jpg` + 压 0.82 那档，阅读屏整屏看得见那张图）。**还没量到的是**：挑一支字体之后全应用的字形真的换了、以及选错文件那两句实话。
  测试文件已备在 `/sdcard/Download/`（`bgtest.png` 一张截图、`testfont.ttf` 是 `/system/fonts/NotoSerif-Regular.ttf` 的拷贝），
  下次屏幕空出来一枪就能走完；走完要把 `testfont.ttf` 那一步的产物用「恢复系统字体」清掉。
- **漫画的目录抽屉列整本**（章名来自下载时存下的 `outline.txt`），没下的那几行灰着、点了只说一句"还没下到本机"；
  瓜子那家另有「全彩版 68 卷」这种**再版话**，它的 id 比正文话大、故事却早，所以按 id 排和按页面顺序排会给出两种结果 ——
  判据钉的是"页面倒着、我们正着"（`chapters.last() == 页面第一行那一话`），不是"第 N 话一定在第 N 位"。
- **漫画的书签只在这本书的屏里**：底栏「书签」开的是这一层（记当前页 / 跳 / 删）。
  底栏那一格「书签」（全书那一页）**还不认漫画的条目** —— 那一页读的是 `marks.<id>`（章号+字符偏移）和 pdf 那族的 `pageMarks.<id>`，
  漫画存的是第三串 `comicMarks.<id>`。要它出现在那一页，得给那一页加一种"第几话第几页"的行，没做。
- **漫画的「增量更新」要重读每一话的页面**：图片地址只在章页里，判"这一话有没有新页"就必须先把那一页拿下来 ——
  所以图全在盘上时点一次更新 = 每话一次请求（图库漫画那本 435 话就是 435 次），不再重下图。
  小说那一条是"章缓存在磁盘上就一个请求都不发"，漫画做不到同一件事，原因写在 `ComicDownloader.fetchChapter`。
- **漫画没有听书、没有字号/行距那一套**：那一族整屏都是图，`ReaderScreen` 的长按选段 / 词典 / 合成
  全都挂在文字上，接不过来；版式只有亮度 + 背景两样（底栏那颗「设置」里）。
  进度和书签都是「第几话第几页」，`ReaderPrefs.comicProgress` 报的是「第 N 话」，
  书架那一行因此不摆「N 章未读」（算不出，摆一个数就是假话）。
- **文献源没有目录、没有"先拉开头"**：一篇就是一支 PDF，所以搜书那一行上它只有一颗「下载 PDF」。
  `SearchEngine.head()` 在这种源上会直接报"这条源没有 toc 那一段"而不是回一本 0 章的书。
  OpenAlex 的摘要是 `abstract_inverted_index`（词 → 位置），还原后有洞的那条会在末尾写「摘要读到这里为止」。
- **第二次点同一本书改成增量，靠的是书架上那本的 `source.tsv`**：这一版之前重复下过的（他架上那三本同名《夜无疆》）
  不会自动并成一本 —— 只清得掉「以后」的重复，历史遗留要他自己在书架长按删掉多余的。
  增量那一趟仍然把整本**重新入库**一次（章缓存在磁盘上，所以不发请求，但 chunk/chapter 索引是重建的）：
  一本 423 万字的约一秒，不是零成本。真"往末尾追加"要引擎级改成按章存储，那一条动的
  是分页、阅读进度、听书缓存三处键，没做。
- **`kind` 不认写错的那一条源**：只认 `novel` / `comic` / `audio` / `paper`，导入时就报"只认这些"，
  所以手抄源文件的人要看得懂那四个词（管理页里那条源的失败原因会原话贴出来）。
- **有声这一档随包只有两条源，内容面比小说那几条窄**：一条走公开播客 RSS 的口子（`podcast-rss`），
  搜到的是各家**自己按协议公开分发**的那批节目；评书/长篇有声小说在这种源里不多，且随时可能被站点自己挪走
  （CRI 那 19 条 feed 的首集 17 条已经回 423，是同一天的实测）。想听某一本具体新书，仍然得自己导一条源。
- **有声书一集的字节是一次读进内存的**：`HttpFetcher` 走的是 `inputStream.readBytes()`，没有流式落盘那一档。
  一部 60MB 的段就是 60MB 的瞬时堆占用（漫画一张几百 KB，同一行代码从来没暴露过这件事）。
  小说/漫画/文献都没这问题，所以这一条现在只写在缺点里，没去改公共取页层。
- **有声播放器没有通知栏和锁屏控制**：没挂 `MediaSession`、没起前台服务、没加唤醒锁 ——
  下拉栏里没有那排播放/暂停/跳过，锁屏上也没有；息屏多久会被系统收回进程**没量过**，
  但按这一族的实现（播放器活在 `AudioReaderScreen` 的组合里）退出那一屏就是 `close()`。
  小说的 AI 听书也是同一档实现，所以这不是有声书新引入的洞，是这一族共同的天花板。
- **有声不抢音频焦点**：开着别的音乐/播客进来听，两边一起响（`AiVoicePlayer` 只有"混播"那一档会去申请
  `AUDIOFOCUS_NONE`，默认那一档什么都不申请）。要做成"一开播别人自动停"，得补 `AUDIOFOCUS_GAIN` + 焦点丢失时暂停的回调。
- **有声书没有书签**：进度只有「第几集 + 第几毫秒」一格（`audio.<id>`）。书架那两栏因此不摆「N 章未读」，
  和漫画/文献同一个理由：算不出，摆一个数就是假话。
- **跟读只在"音频和正文在同一页"那一族有**（随包里就是古文岛那一条）：播客那一族站点不给正文，
  那一屏还是封面 —— 这不是缺实现，是那一条源根本没有可跟的文字。
- **跟读的时刻是估出来的**：站点不给时间轴，只能按字数线性摊（量法、两把尺子的读数都写在 `FollowAlign` 顶上）。
  因此界面上**没有写过"误差几秒"这种话** —— 回内那一档量不准：停顿那把尺子的地板就是 1.1 秒
  （停顿平均 4.6 秒一条，什么预测都吸附得上），音节那把四组参数互差 16–25 秒，比信号还大。
- **跟读的"零点"补上了，机器上对到 33 毫秒**：录音开头先把**回目＋作者**念一遍才念正文，而站点给的正文里没有
  这一句（`div.contson` 从正文第一个字开始）。四回书实测第一处长停顿在 **6.14 / 3.76 / 7.00 / 6.18 秒**，
  按「(回目＋作者) 字数 × 0.28 秒/字」推出来是 6.16 / 6.16 / 7.00 / 6.16 秒 —— 三回对到 0.1 秒内。
  不补就是整张表一开始就比声音早 6 秒 ≈ **一整句**。现在跟读文本第一行摆的是「集名 + 作者」，
  真机上读应用自己算的那一格：**正文第一句表起 6917ms，音频真开口 6950ms —— 差 33 毫秒**。
- **表算到后半集会往后拖，这一条是真机量出来的**：`FollowAlign.align` 原来分母拿 `count(整段)`、分子一格一格
  加的是 `count(每句)`，而半格是**往上取整**的 —— 一段里每多一句就多进一位。红楼梦第一回 67 段，
  分母因此少 56 格 = 每一格被放大 0.77%，**越到后面越晚**：机器上 30:04 那一句表上写 1801927ms、
  按音频该是 1788 秒，**晚了 13.9 秒 ≈ 两句**（他这一轮报的"又慢了"）。改成分子分母数同一批量之后
  同一处只差 1.4 秒，判据钉在 `theWeightsOfTheSentencesAreExactlyTheWholeTimeline`。
- **多段的那一集不开跟读**：`durationMs` 是**当前那一段**的时长，拿它摊一整集的字数会把后面几段该念的句子
  全算进第一段。所以那一集顶栏不摆「正文」这颗，中间仍是封面。
- **跟读的观感只量到"毫秒"这一层**：真机上验的是表上时刻对音频真开口（33 毫秒 / 1.4 秒那两条），
  红字在屏幕上跟不跟手、滚得顺不顺，仍然只有他眼睛能判。


- **pdf / pptx 没有版式可调**：整页渲染、保留原件版面，所以阅读页那套字号 / 行距 / 边距 / 段首缩进 /
  纸色六档对它一概不生效，顶栏右侧因此明写了「原版面」。这一类只有三个动作：
  **翻页** = 点屏幕左右 1/3（分界数学和阅读页同一颗 `ReaderGestures.zoneOf`，core 里有判据；中间 1/3 收放上下两条栏，
  「点击两侧均翻到下一页」那棵开关也照读；没放大时还能左右滑）；**放大** = 双指在页面上张合，1.0~3.0 倍整页等比
  （形状、图片、表格、文字同一个比例），放大后单指拖着看局部（pdf 竖向仍走列表、ppt 的翻页滑动让给拖动）；
  **播放**（只 pptx，在抽屉顶行、「前往」左边那颗「播放 / 暂停」）= 一页一页往前放，速度那一排选
  `慢 12s / 中 8s / 快 4s`（点一档就开始放），走到最后一页自己停下、那颗按钮跟着回到「播放」。
  抽屉**就是这一类的底栏本身**：点屏幕中间把上下两条栏放出来，下面那条直接是它，不再"点页码再弹一层"。
  版式照他给的那张图：顶行左「取消」纯文字、右「前往」实心强调色（图里那颗「创建」），
  **中间那对分段控件没做**；下面圆角输入框（只收数字，占位「输入要跳到的页数」）+ 一行「第 N / M 页」。
  外壳和另外两个底部抽屉同一份规矩（顶上一对圆角走常量 `SHEET_RADIUS = 10dp`、空白自己吃点击、`imePadding` 让键盘抬起来）；
  「取消」和「前往」都先收键盘。原来那颗模态「跳页」框删了，底栏不再单独显示页码。
  pdf 正文的底部留白跟着抽屉自己量上来的高度走（`onHeight` 报上去），不写死一个数。
  抽屉和滑轨都撤了。**pptx 没有单独的"字号"旋钮**：定版面里形状框装不下时 PowerPoint 会先把字缩小以适应，
  用户倍数乘在它之下会被框顶死（真机量过：选 155% 时生效值反而掉到 31%、版面几乎没动 = 白按），乘在它之上又会盖出框外
  并把版面挤乱 —— 两害相权，放大整页是唯一入口。缩放/播放是这一屏的临时状态，不落库（没有"复位"那颗按钮了，
  存着一个 2.5 倍下次打开反而看不出为什么）。
  pdf 的位图只渲到 2 倍为止：一张 3 倍的 A4 是 3240x4583 = 59MB，会把按 `maxMemory/4` 的那格 LRU 挤得只装得下一页，
  而 2 倍时正文已经约 40px 高 —— 再往上只是摊大已有像素，不是多要细节（这条是算出来的，不是量出来的）。
  也**没有分栏**。夜间模式不反色 pdf（反色会把扫描件变成看不清的东西）。
- **pptx 只画文本框、图片和表格**：按形状自己的 EMU 位置等比铺到屏宽，run 级的粗体/斜体/字号/颜色都跟着；
  母版和幻灯片背景、SmartArt、图表、动画、演讲者备注都不画（`graphicFrame` 里只认 `a:tbl`）。`.ppt`（97 二进制）
  直接拒并回一句"另存成 .pptx 再导入"——这条分支手上没有 .ppt 样本可打，只按代码路径确认（它排在 txt 兜底之前，
  不会被当纯文本吞成乱码）。
- **mobi / azw3 只认「不压缩」和 PalmDOC LZ77**：HUFF/CDIC 压缩、DRM 加密的直接拒，并把原因写在回话里
  （这种书用 Calibre 转成 epub 再导入最快）。AZW3 是 MOBI6+KF8 双份，读的是它自带的 MOBI6 那一份：正文一样，标记老一点。
- **epub / docx 抽的是纯文本，不保留原书样式**：加粗、斜体、图片、脚注、原书自己的缩进都没了，章节靠正文里的标题行重新认。
  这是"喂给同一个排版器"这条路的代价 —— 换来的是除 pdf 之外所有格式共用一套版式和位置模型。
- **markdown 只到"这一层标记"为止**：图片 `![…](…)` 换成一行占位「〔图〕alt」不显示真图（md 里的图基本都是相对路径，
  入库后就找不到了）；表格是原样竖线文本，不对齐也不画框；代码块整块等宽、没有语法高亮；链接**没有独立颜色**——
  量过：同一行里「纵横中文网」和它前后正文的通道均值 B−R = +8.9 / +8.7，是同一档，等于没区分（我们商定的那一档
  没包含链接样式；要就加下划线或主题强调色）。嵌套列表超过两级没测过。
- **markdown 的斜体是合成的，而且这一处还没复量**：这台机的 CJK 字体没有真斜体，`Typeface.create(base, ITALIC)`
  画回来和正体逐位相同（真机 A/B：普通与"斜体"的「山水风云」墨数 1098 = 1098、上/中/下 1/3 质心 77.74 / 72.27 / 68.78 全等，
  差 0.00），所以绘制端给 ITALIC 那一段加了 `textSkewX = -0.22` 自己剪。改完 APK 编过了，但截图那一枪前台又被他的
  `com.xiaojoo.lightplayer` 占着，没去点他的应用。**预期读数**：斜体那组的"上−下 1/3 质心"从 +8.96px 抬到 ≈+13.8px
  （0.22 × 那两段质心相距的 22px），普通那组仍是 +8.96px。符号不是猜的：SDK 的 `Paint.setTextSkewX` 文档原话是
  "For approximating oblique text, use values around -0.25"；真要是量出来方向反了，翻符号就行。
- **夜间模式是真的**：`Chrome` 从一堆常量改成"一颗可观察的 `night` + 白天/夜间两套 `Palette`"，
  外壳四页和状态栏/导航条都读它。真机量过：开一下开关，我的页底色 (246,247,249)→(18,19,22)、卡片 (255,255,255)→(27,28,32)、
  状态栏 (246,247,249)→(18,19,22)，再关回去三处逐位复原，`theme` 读回 0。夜间那套的墨色/强调色取自
  `ReaderTheme.Night` 同一批值，两处不会各说一套。开夜之前的那档纸色记在 `dayBefore` 里，关夜还回原来那档（不是一律拍回纸白）。
- **分界线一律 1 个物理像素**：`1.dp` 在这台机（2.75 倍密度）取整成 3 行。我的页行间的线改成按密度换算的 1px，
  真机沿 x=540 竖向切：只有 y=427 一行是 (227,231,237)，其余全是卡的白；搜索页那条同样改法的线此前量过是
  203:0 / 204:0 / 205:78 / 206:0。书架"添加作品"的虚线框从 `1.dp.toPx()`(=2.75) 改成 `1f`，同一规则，
  这一处还没在屏幕上复量（见下条）。
- **随包的默认源只有两条**（梦书中文、爱下书小说网），进来的条件是搜索页、目录页、正文页三格都从这台机取回真页面判过；删了不会自己回来，「管理书籍源」里那颗「恢复随包」按包里那份换回来（这条是补的：没有它，随包规则改了永远到不了已经种过一次的手机）。
  内置名单会腐烂 —— 参照物 so-novel 那 25 条里，光它自己注释就标了 5 条毛病（搜索关闭 / CF 盾 / 章节 JS 加密 / 限流要降线程）。燃文小说网原来在包里，按它自己的正文页判过之后摘了：正文是 `document.writeln(qsbs.bb('BASE64'))` 拼的，剥掉 script 只剩 4 段 / 720 字广告，下载进度照样走到 100%。
  爱下书那条带着一处**站点自己的数据错**进来：《剑来》最后 83 章的页面面包屑仍写剑来，正文是另一本书 —— DOM 里没有线索可判，规则治不了；用这条下这本，书尾会多 83 章别人的内容。
- **下载中途退出应用**：任务表是进程内的，回来那一行会退回「下载」；已抓到的章在磁盘上，
  再点一次只补剩下的那几章（不是重下一遍）。
- **精选是静态壳**：只有版式和"未接入书源"的说明，没有榜单/推荐内容；四张卡片是占位。
- **列表模式下没有「添加作品」那颗卡**：入库只剩 ⋯ → 「本地导入」这一个入口（图墙模式两个入口都在）。
  列表那一屏按他给的那张图就是一行一本、末尾不留占位格。
- **封面只能拿源站给的那一张**：下载时抓到 `cover.jpg` 就存下并显示（`DownloadWorker` 落盘，增量更新时按 `KEEP_ON_UPDATE` 保留），
  没抓到就画默认那一档（底色按书名哈希 + 书名横排）。**用户自己带图入库那条口子没做**。
- **搜索的中文输入没法用 adb 直接打**（`input text` 不吃 CJK）：这一轮是把"陈平安/剑来/符纸"先塞进 prefs 的 `recentSearch`，
  再点最近搜索那一行触发真搜索，所以整条路（输入框以外的全部）都验过了；输入框里手打中文那一枪仍要你点一次确认。
- **章末孤行**：`剑来` 每章末尾都有一行 `------------` 分隔线，它会单独占一页。分页没做孤行控制，
  正文也不许动（动了 absoluteOffset 就飘了）。

- 避头点只按一组常见标点位，没有完整行压缩规则；拉丁长词会硬断。
- 没有进度云同步、没有笔记导出、没有 TTS。
- 章节标题识别是启发式五条规则（第X章/节/回…、Chapter N、"1、…"、"001你到底是谁"这种裸编号、序章/番外等）。
  认错会让一章碎掉，所以配了三道兜底：含句末标点的行不算标题、短于 40 字的"章"吞进后一章、
  超过 20 万字的章在段落边界上切开（排版单元必须有界）。仍可能漏掉写法特殊的标题。
